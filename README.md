# AI 协作群聊工作台 (AI Group Chat Studio)

> **面向开发、科研与工程自动化的开源 Windows 多智能体（Multi-Agent）群聊协作与本地终端/代码监控工作台。**
>
> Python 标准库即可启动核心服务 · 单一 SQLite 数据库存储 · 多协议 Function Calling 挂载 · 多步 ReAct 上下文预算控制 · 本地纵深安全防护

## 一、项目简介

**AI 协作群聊工作台 (AI Group Chat Studio)** 支持将多个不同厂商、不同协议的大语言模型（如 OpenAI `gpt-4.1` / `o3-mini`、Google `Gemini 2.5 Pro`、Anthropic `Claude 3.7 Sonnet`、DeepSeek `deepseek-reasoner` 或其他 OpenAI 兼容接口模型）接入同一个本地协作群中。

在这里，你作为**群主**可以：

* **不带 `@` 全群广播任务**：按左侧排列的 AI 上下顺位依次接力执行（第 1 个 AI 完成目录扫描、文档读取、代码编写并输出公开回复后，第 2 个 AI 自动结合包含前序 AI 公开回复的上下文接力完成后续工作）；
* **带 `@AI昵称` 定向指派任务**：仅唤醒被点名的 AI，其余未点名的 AI 保持静默；
* **赋予 AI 本地文件与 PowerShell / CMD 终端操作能力**：在右侧「💻 终端/代码」监控面板实时查看 AI 发起的命令、编写的代码文件与控制台输出；
* **单次读取本地长文档（支持文本代码、`.docx` 及可选增强的 `.pdf` 解析）**：单步最高支持读取 `500,000` 字符，并配合多步工具历史分级折叠策略，降低多步工具调用带来的上下文 Token 消耗；
* **应用状态统一存储在本地 SQLite 数据库 (`ai_group_chat.sqlite`)**：包括免责协议签署状态 (`disclaimer_accepted_v1`)、AI 模型配置与密钥、群聊记录、私密思考日志与工具调用审计均保存在根目录 `ai_group_chat.sqlite` 中，不使用浏览器 `localStorage` 缓存（注：左侧工作区文件列表由后端在读取状态时实时扫描本地工作区目录生成）；
* **AI 上下文可见性控制**：支持将本地工具读取的原始文件内容或中间步骤默认设为「🔒 仅该 AI 与群主可见」，且私密回复与 `<private>` 块不会触发对其他 AI 的公开 `@` 接力，减少跨模型上下文干扰。

## 二、核心特性与实现机制

### 1. 群成员管理与顺序接力调度

* **自由增删与独立启停**：左侧列表支持随时新增、编辑或删除 AI 成员；每个 AI 卡片均提供 `● 已启动 / ○ 已关闭` 与 `🛠️ 工具已挂载 / 无工具` 切换按钮。
* **未配 Key 自动静默**：未填写 API Key 的 AI 显示为 `🔇 未配Key (静默)`，在全员广播或被 `@` 时自动跳过。
* **拖拽换序与 `↑` `↓` 箭头调序**：支持鼠标上下拖动 AI 卡片或点击右上角 `↑` `↓` 按钮调整发言顺位，顺位变更同步保存至 SQLite。
* **顺序执行（接力模式）与并发模式**：
  * **开启顺序执行时（默认）**：群主发送非 `@` 消息或同时 `@` 多个 AI 时，按左侧从上到下的顺序依次执行；后续顺位 AI 自动接收包含群主原始指令与前序 AI 公开回复的历史上下文（仅当上下文末尾消息恰好等于触发该任务的源消息本身时才剥离去重，保留前序 AI 的公开回复）；若前一个 AI 在最终公开回复中 `@` 了顺位中的下一个 AI，系统会更新队列项而不重复排队。
  * **关闭顺序执行时**：所有被唤醒的 AI 并发请求与流式输出，工具权限审批与紧急打断请求进入各自的 **FIFO 审批队列**，按先后顺序逐个弹窗确认。
* **`@` 唤醒规则与私密内容过滤**：仅当公开消息正文中包含 `@对方昵称` 时才触发唤醒；整条标记为私密（`[仅自己和群主可见]` / `[PRIVATE]`）的消息不会触发 `@` 接力，且在解析 `@` 提及与向下一位 AI 组装上下文前会先剔除 `<private>...</private>` 与 `<self_only>...</self_only>` 块。

### 2. 多协议本地工具挂载、分级上下文预算与步数上限收尾

* **四大主流协议支持（前后端均支持 System Prompt 注入与交替角色合并）**：
  1. **OpenAI Responses 协议** (`/v1/responses`, `wire_api = "responses"`)
  2. **OpenAI Chat Completions 协议** (`/v1/chat/completions`, `wire_api = "chat"`)
  3. **Google Gemini 原生协议** (`v1beta/models/...:streamGenerateContent`，通过 `systemInstruction` 传递系统提示词，并合并连续同角色消息)
  4. **Anthropic Claude 原生协议** (`/v1/messages`，通过顶层 `system` 字段传递系统提示词，支持 `thinking` 预算并合并连续同角色消息)
  5. **文本标签回退解析**：若自定义 API 网关剥离了原生 `tools` 字段，前端支持解析正文中形如 `<tool_call>{"name": "...", "args": {...}}</tool_call>` 的调用块。
* **内置 6 项工具**：
  * `read_local_file(file_path, file_paths, share_with_other_ai)`：单次读取本地文件内容（单次返回上限 `500,000` 字符，支持传入 `file_paths` 数组批量读取）。其中：
    * `.docx` 文档：使用 Python 标准库 `zipfile` + `xml.etree.ElementTree` 直接解析段落与表格文本；
    * `.pdf` 文档：优先调用本地 Python 环境中已安装的 `PyMuPDF (fitz)`、`pypdf`、`PyPDF2` 或 `pdfplumber` 提取分页文本；若当前环境未安装上述可选库，则回退至基于标准库 `zlib` 的基础文本流提取（对采用复杂字体编码或压缩流的 PDF，建议通过 `pip install pypdf` 安装可选依赖以获得完整解析效果，扫描件图片 PDF 不支持纯文本提取）。
  * `write_local_file(file_path, content, share_with_other_ai)`：新建或覆盖写入本地文件（自动创建父目录）。
  * `list_local_directory(dir_path, share_with_other_ai)`：列出指定目录中的文件与子目录（最多返回前 250 项）。
  * `run_powershell_command(command, cwd, share_with_other_ai)`：调用系统 `powershell.exe` 执行命令并捕获 `stdout / stderr`（默认超时 90 秒，单次输出上限 150,000 字符）。
  * `run_cmd_command(command, cwd, share_with_other_ai)`：调用系统 `cmd.exe /c` 执行命令并捕获输出。
  * `ask_other_ai(target_ai, message, is_urgent)`：向群内其他 AI 发起协作或紧急插队请求。
* **多步 ReAct 工具历史分级折叠策略（`buildBoundedStepToolHistory`）**：
  在单个任务的连续多步工具调用循环中，为兼顾当前步完整读取与后续步 Token 成本控制，系统按以下分级阈值组装当前任务的 `selfStepToolHistory`：
  1. **最新一步（`idx === totalSteps - 1`，即刚执行完的工具）**：最高完整保留 `500,000` 字符（若超出 `500,000` 字符，则保留前 `380,000` 字符与后 `100,000` 字符），确保模型在调用 `read_local_file` 读取几十万字源码或文档时，当步不会因中间段落被截断而反复调用命令切片补读；
  2. **紧邻的倒数第二步（`idx === totalSteps - 2`）**：仅当该步输出不超过 `24,000` 字符时完整保留；若超过 `24,000` 字符（例如上一步刚完整读取过的长文件），则在进入下一步时自动折叠为头尾摘要（保留前 `2,400` 字符 + 后 `1,200` 字符），避免在后续步骤中重复上传整份大文件；
  3. **更早的历史步骤（`idx < totalSteps - 2`）**：输出超过 `4,000` 字符时自动折叠为头尾摘要（保留前 `2,400` 字符 + 后 `1,200` 字符）；
  4. **聊天区工具卡片去重**：聊天界面展示的当前 AI 中间工具步骤卡片（`is_tool_step_log = true`）不会重复拼入该 AI 的群聊历史消息数组。
* **达到工具步数上限时的总结收尾**：若 AI 连续调用工具达到 `max_tool_steps`（默认 15 步，可设 3～30 步）且最后一步仍返回工具调用，循环会额外执行一次关闭工具挂载的汇总请求（`isFinalSummaryStep`），要求模型基于已有工具结果输出总结汇报。

### 3. 上下文可见性控制与实时监控栏

* **工具输出默认仅自己与群主可见**：本地工具调用产生的中间卡片默认设置 `only_self_and_owner = true`（除非模型显式传入 `share_with_other_ai = true` 或群主手动点击消息下方的可见性切换按钮），不会拼入其他 AI 的上下文。
* **右侧四合一监控栏**：
  * **思考过程**：流式展示支持推理模型的思考链；在流式阶段使用 `requestAnimationFrame` 合并渲染帧，并在 DOM 中滑窗显示最新 `14,000` 字符（内存中单条思考保留上限为 `120,000` 字符，归档后裁剪至 `35,000` 字符），降低长时间思考时的页面重排卡顿。
  * **💻 终端/代码**：展示模型工具调用的参数流（`tool_delta`）、执行的命令、退出码、耗时及文件读写结果。
  * **队列/挂起**：展示全局顺序接力队列、各 AI 的 FIFO 待办队列与紧急打断挂起栈（Suspended Stack）。
  * **工具审计**：展示当前会话统计与本地工具调用审计记录。

## 三、本地安全防护机制与安全边界说明

针对本地 Web 服务常见的 **DNS Rebinding**、**跨站请求 (CSRF)**、**前端明文密钥暴露** 与 **DOM 属性拼接** 风险，项目实施了以下防护措施，但使用者需同时了解其适用边界：

### 1. 已实施的防护措施

1. **绑定本机环回地址 (`127.0.0.1`)**：服务端仅监听 `127.0.0.1`（端口范围 `18765~18800`），不直接暴露于局域网或公网网卡。
2. **`Host` / `Origin` / `Referer` / `Sec-Fetch-Site` 请求头校验**：拒绝 `Host` 非 `127.0.0.1` / `localhost` / `[::1]` 的请求以及跨站请求头，缓解通过浏览器发起的 DNS Rebinding 与跨站调用风险。
3. **256-bit 随机进程会话令牌 (`X-Session-Token`)**：服务端每次启动通过 `secrets.token_urlsafe(32)` 生成随机令牌并注入首屏 HTML；所有 `/api/*` 请求均需携带匹配的 `X-Session-Token` 头，且服务端不返回跨域允许头（CORS）。
4. **API Key 服务端脱敏返回**：`GET /api/state` 接口对已保存的 API Key 返回占位符 `__STORED_IN_SQLITE__` 与掩码预览（如 `sk-••••xxxx`），由 Python 后端在发起模型请求时从本地 SQLite 读取明文密钥。
5. **免责状态校验、一次性审批票据 (`approvalTicket`) 与常见敏感路径拦截**：
   * 未在 SQLite 中记录同意免责协议前，后端拒绝 `/api/llm/stream` 与 `/api/tool/execute` 请求；
   * 在「每次询问批准 (`ask`)」模式下，`/api/tool/execute` 校验由 `/api/tool/issue-ticket` 签发的、与工具名及参数规范化 SHA-256 哈希绑定的一次性票据（有效期 5 分钟，单次消费即失效）；
   * 文件读写与工作目录检查内置常见系统敏感路径黑名单（拦截对 `.ssh`、`.gnupg`、`.aws`、`.kube`、Windows `Startup` 启动目录、`C:\Windows\System32` 等路径的直接工具路径访问）。
6. **内联事件参数转义 (`escapeJsAttr`)**：动态渲染到 HTML 内联 `onclick` 等属性中的字符串参数经过 `JSON.stringify` 与 `escapeHtml` 转义，避免含单引号 `'` 或特殊字符的昵称/文件名破坏属性语法。

### 2. 安全边界与风险提示（重要）

* **非操作系统级沙箱**：本软件的敏感路径黑名单仅覆盖常见系统高危目录且主要针对工具路径参数，**不能替代容器、虚拟机或操作系统级强制访问控制（沙箱）**。
* **终端命令执行风险**：当您批准 AI 执行 `run_powershell_command` / `run_cmd_command` 或切换为「全部自动允许 (`allow`)」模式时，子进程将以您当前登录的操作系统用户权限运行，命令内部仍可能访问或修改您用户权限范围内的文件与网络资源。请仅在受信任的本地环境中使用，并在批准前仔细核查每一条命令与文件路径。
* **浏览器直连兜底路径说明**：当通过 `python app.py` 正常启动本地桌面服务端时，请求走服务端代理与脱敏密钥；若仅将 `static/index.html` 作为纯静态网页在无后端环境下打开预览，则无法使用本地 SQLite 与真实磁盘/终端工具。

## 四、运行环境与依赖说明

### 1. 依赖构成（核心标准库 + 可选增强依赖 + 前端 CDN）

* **操作系统**：Windows 10 / Windows 11（亦可在 macOS / Linux 下运行核心服务）。
* **Python 环境**：Python 3.9 及以上。
  * **核心服务无强制第三方 Python 包依赖**：启动 `app.py`、本地 SQLite 存储、SSE 流式代理、`.docx` 文档提取及终端命令执行均仅使用 Python 标准库，无需预装第三方包即可直接运行。
  * **PDF 解析可选依赖**：若需解析复杂字体编码或压缩结构的 `.pdf` 论文/文档，建议在本地 Python 环境中安装 `pypdf`（`pip install pypdf`）或 `PyMuPDF`（`pip install pymupdf`）。未安装时将回退至基于标准库 `zlib` 的基础文本流提取。
* **前端样式资源**：`static/index.html` 默认通过 `<script src="https://cdn.tailwindcss.com/3.4.17"></script>` 加载 Tailwind CSS Play CDN（浏览器首次打开时需联网加载样式脚本；如需在完全离线的内网环境使用，可将 Tailwind 样式编译为本地静态 CSS 文件后引入）。

### 2. 启动方式

解压项目文件夹后，任选以下一种方式启动：

* **方式 A（推荐，带控制台日志）**：双击运行 `run_windows.bat`
* **方式 B（静默无控制台窗口）**：双击运行 `launch_app.vbs`
* **方式 C（命令行启动）**：
  ```bash
  python app.py
  ```

启动后，程序会在本地 `127.0.0.1:18765`（若被占用则顺延至 `18765~18799`）启动服务端，并调用系统默认浏览器打开工作台页面。

## 五、使用指南

### 1. 首次启动与免责协议确认

* 首次打开工作台时，会弹出《GNU AGPLv3 开源软件许可与全面免责声明协议》。请阅读根目录下的 `免责协议.txt` 并勾选同意后进入工作台（签署状态保存在根目录 `ai_group_chat.sqlite` 的 `settings` 表中；可随时点击顶部栏的 **「📜 免责协议」** 按钮复查）。

### 2. 配置群内 AI 模型与 API Key

1. 点击左侧 AI 卡片上的 **「配置」** 按钮（或顶部 **「+ 添加 AI 模型入群」**）。
2. 选择对应的**接口协议类型**：
   * `OpenAI Responses 协议 (/v1/responses)`：适用于支持 Responses API 的模型（如 `gpt-4.1`、`o3` 等）。
   * `OpenAI Chat 协议 (/v1/chat/completions)`：适用于标准 OpenAI、DeepSeek (`https://api.deepseek.com/v1`)、vLLM、Ollama 等兼容接口。
   * `Google Gemini 原生协议`：默认地址 `https://generativelanguage.googleapis.com/v1beta`。
   * `Anthropic Claude 原生协议`：默认地址 `https://api.anthropic.com/v1`。
3. 填入 **API Key** 与 **模型标识符 (`model`)**。
4. **透明可编辑的 System Prompt**：在下方「完整系统人设、协作纪律与工具使用说明」框内，可直接查看或修改发送给该 AI 的完整系统提示词（已保存的自定义提示词在重启后不会被默认模板覆盖）。
5. 点击左下角 **「📤 导出 AI 配置」** 或 **「📥 导入 AI 配置」** 可备份或恢复配置。

### 3. 本地工作区文件编辑与聊天记录导出

* **本地工作区文件保存**：在左侧「本地 Agent 工作区」点击文件（或「+ 新建文件」）修改保存时，前端会等待后端写入磁盘校验通过后再关闭弹窗并刷新列表；若路径触发后端安全拦截或磁盘写入失败，弹窗将保持打开并提示具体错误原因。
* **导出聊天记录**：点击顶部栏 **「📥 导出聊天记录」** 按钮，可将当前群聊记录导出为 **Markdown (`.md`)**、**纯文本 (`.txt`)** 或 **JSON (`.json`)** 文件（勾选附带私密思考过程时，每个多步任务仅在该任务的最终回复下附带一次完整思考记录，不会在中间工具步骤下重复导出）。
